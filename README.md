# Edge Collector

基于 Linux C++ 的可靠边缘数据采集与传输网关。

## 1. 项目简介

Edge Collector 模拟工业设备的数据采集场景，由设备模拟器（Device Simulator）、边缘网关（Gateway）和中心服务（Center）三个部分组成。

项目重点解决网络中断、中心服务不可用、重复消息、异常数据和多设备并发接入等情况下的数据可靠传输问题。

设备消息首先由网关持久化到本地 SQLite 数据库，成功后向设备返回 `GATEWAY_STORED`。网关通过后台线程将待传数据发送至中心，收到中心持久化确认后更新本地送达状态。

## 2. 技术栈

- 开发语言：C++17
- 运行环境：Linux / Ubuntu
- 网络通信：TCP Socket、长度前缀消息协议、poll
- 并发控制：std::thread、mutex、atomic
- 数据持久化：SQLite3、WAL、事务
- 构建与测试：CMake、CTest、Git

## 3. 系统架构

```text
Device Simulator
       |
       | TCP :9000
       v
+---------------------------+
|          Gateway          |
|                           |
|  客户端工作线程             |
|          |                |
|          v                |
|  消息校验与幂等检查         |
|          |                |
|          v                |
|  SQLite Outbox            |
|          |                |
|     后台补传线程            |
+----------|----------------+
           |
           | TCP :9001
           v
+---------------------------+
|          Center           |
|                           |
|  消息去重与 SQLite 持久化   |
+---------------------------+
```

网关与中心分别使用独立的 SQLite 数据库。

## 4. 核心功能

### 4.1 本地持久化与 ACK

网关先将消息写入 SQLite，事务提交成功后才向设备返回 `GATEWAY_STORED`。

该 ACK 仅表示网关已完成本地持久化，不代表中心已完成接收。

### 4.2 断线补传

中心离线或网络异常时，网关保留未送达消息。

后台补传线程定期扫描待传记录，并在中心恢复后重新发送。收到中心持久化确认后，将记录更新为 `delivered=1`。

### 4.3 幂等去重

设备消息包含设备 ID 与事件 ID。网关使用 `(device_id, event_id)` 识别重复事件，避免重复写入。

中心侧根据消息 ID 进行去重，处理 ACK 丢失导致的重复发送。

### 4.4 异常记录隔离

对于无法通过重试解决的永久性错误，网关将对应记录标记到隔离表，避免异常数据反复占用补传流程。

原始数据保留，便于排查。

### 4.5 多设备并发

网关采用每连接一个工作线程的处理方式，主线程负责接入连接。

当前实验配置限制为最多4个并发客户端，并支持已结束工作线程的回收和程序优雅关闭。

### 4.6 网络超时与性能优化

使用超时控制和 poll 处理连接等待与空闲设备。

针对短消息的长度帧头和正文分开发送问题，通过客户端、网关两端的 `TCP_NODELAY` 配置对 ACK 时延进行优化，并开展了对照测试。

## 5. 编译

依赖：C++17 编译器、CMake、SQLite3 开发库及 pthread 支持。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
```

运行单元测试：

```bash
ctest --test-dir build --output-on-failure
```

## 6. 运行

在项目根目录创建运行数据目录：

```bash
mkdir -p data
```

终端1：启动中心服务。

```bash
./build/center
```

终端2：启动网关。

```bash
./build/gateway
```

终端3：启动设备模拟器。

```bash
./build/device_sim
```

示例设备消息：

```text
device01|event1001|1001|1792200000000|25.6
```

消息包含设备ID、事件ID、序列号、时间戳和温度。

设备与网关、网关与中心采用基于 TCP 的长度前缀分帧通信，帧头为4字节网络字节序的消息长度。

## 8. 性能结果

在 VMware Ubuntu、4个并发客户端、1000条消息的单轮测试条件下：

| 配置 | ACK吞吐量 | P95时延 |
|---|---:|---:|
| 双端默认TCP | 48.18条/s | 84.79ms |
| 双端启用TCP_NODELAY | 1542.37条/s | 5.61ms |

双端启用 TCP_NODELAY 后，ACK 吞吐量约为原来的32倍。

该指标仅表示设备到网关本地持久化确认的性能，不等于中心最终入库吞吐量，也不代表生产环境下的最大设备容量。

## 9. 已知限制

- 当前使用每连接一个工作线程的架构，并非线程池或 epoll Reactor。
- 实验并发上限为4，未验证大规模设备接入容量。
- 当前性能测试主要在单台 VMware 虚拟机环境下完成。
- 现有 CTest 自动化覆盖以消息解析为主，其他集成和故障测试仍需进一步自动化。
- 当前未实现完整的跨网络安全认证、加密传输和生产级运维监控。

本项目主要面向 Linux C++ 网络编程、可靠传输和边缘网关工程实践。
